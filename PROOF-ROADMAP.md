# Proof Roadmap — from computed to proved

Started 2026-08-22. The book (Appendix E) and the blog make categorical
claims that are *asserted*; the ecosystem's verification (`pflow verify`,
`petri_verify`, ZK provers, one hand-written Lean file) proves *algebraic*
properties of single nets. This roadmap closes the gap, in leverage order.
Status is kept here; each item names the repo it lands in.

## Inventory (what is already proof)

| Capability | Where | Kind |
|---|---|---|
| P/T-invariants, `structural` verdicts (any initial marking) | go-pflow `pflow verify`, petri-pilot `petri_verify`, sim `sim_invariants` | linear-algebra proof |
| deadlock-free / bounded / live / mutex / unreachable | `pflow verify` | exhaustive or witness |
| 1-safety, every structural P-invariant, confluence — `by decide` | `pflow-polyglot/lean/proof.lean`, **generated** from `model.json` by `tools/codegen -lang lean` (P1) | **kernel-checked** |
| transition validity, 128 B | pflow-rs `pflow-zk-arkworks` / `-risc0`, bitwrap-io | cryptographic, one step |
| composition by pushout | pflow-jl `glue` (AlgebraicPetri `oapply`), petri-pilot `sim_compose` | construction (oracle, not proof) |

## Items

### P1 — Lean from `model.json` (pflow-polyglot)
Make the `proof` form *generated*: `tools/codegen` emits `lean/proof.lean`
from `model.json`, so every model gets kernel-checked theorems, not just
the coffee machine. Theorems per model: 1-safety over the reachable set
when capacities are 1; every structural P-invariant found from C holds on
every reachable marking; final-marking confluence when the net is
conflict-free. Gate: generated file byte-matches the hand-written one for
the canonical model (or the hand-written one is replaced and `make
parity-native` still passes), and `lean` accepts it.
**Status:** done 2026-08-22. `tools/codegen -lang lean` emits `lean/proof.lean`; `make generate` / `make check-generated` cover it; lean 4.33 accepts it and the trace matches `parity/trace.golden`. Theorems: `reachable_closed`, `reachable_one_safe`, `invariant1..4_conserved` (left-nullspace basis of C, RREF over ℚ scaled to primitive integers), `unique_deadlock` (conflict-free nets with one terminal marking). Note: the all-ones vector is *not* an invariant of the coffee machine (`PourCoffee` destroys tokens); the one semi-positive invariant is `Payment + Pending + Sent = 1`.

### P2 — Netting experiment (pflow-jl)
Glue a ρ > 1 *netting* transition into Settle and record what survives:
which P-invariants lift from the parts to the composite, whether the
event-graph property (λ's domain) survives, and whether AlgebraicPetri can
glue along a transition at all (structured cospans expose *species*). The
empirical test of Appendix E's "invariants lift across gluing along places;
liveness does not."
**Status:** done 2026-08-22 — `pflow-jl/test/test_netting.jl`, `docs/netting-experiment.md`. Findings: gluing `net_abc` (ρ = 3) along the pending places gives 7 places / 7 transitions; the composite's left nullspace is one-dimensional, `(1,1,1,1,1,1,3)` — so the cycle's `ones(6)` does **not** lift by zero-extension, while every composite invariant *restricts* to a valid invariant of each part. Appendix E's "P-invariants of a component are still derivable from the composite" holds in the restriction direction only; corrected wording pending (see Later). Event-graph property breaks exactly at the pending places (two consumers each) and `cleared`. AlgebraicPetri's `Open` is species-only (`Open(A,[:t])` → KeyError) but Catlab's `OpenACSetTypes(LabelledPetriNetUntyped, :T)` composes along transitions. Liveness counterexample confirmed by bounded BFS.

### P3 — Sub-SMC closure check (pflow-jl / Catlab)
"Settle is the sub-SMC of OPetri generated by send/settle" — make closure
checkable: a predicate for membership in the generated class, and a check
that `glue`/`⊗` of members stays in the class (property-based over random
wirings), with a Catlab ACSet schema formulation if it fits.
**Status:** done 2026-08-22 — `pflow-jl/src/settle.jl`, `test/test_closure.jl`, `docs/settle-closure.md`. Membership predicate (T1 one-in/one-out multiplicity 1; T2 balance/pending 2-colouring; T3 pending has one producer and one consumer), random-wiring closure check with negative controls, and a Catlab `SchSettleNet` schema with the forgetful Δ-migration to `LabelledPetriNet`. Not a proof of closure — the doc says so; T1–T3 ≡ "generated by send/settle" is argued, not machine-checked.

### P4 — The theorem (Lean)
Formalise and prove: **P-invariants lift across pushout along places.** If
`y₁ᵀC₁ = 0` and `y₂ᵀC₂ = 0` and `y₁`, `y₂` agree on identified places, then
the induced `y` is a P-invariant of the glued net. Core Lean 4 preferred
(nets as finite pre/post functions), mathlib only if unavoidable. This is
the statement every compositionality claim in the book rests on.
**Status:** done 2026-08-22 — `book-pflow-xyz/proofs/` (lake project `PflowProofs`, core Lean 4.33, no mathlib, zero `sorry`). `invariant_lift`: if `y₁`, `y₂` are invariants of `N₁`, `N₂` and `y` agrees with them along the place map `f : P₁ ⊕ P₂ → Q`, then `y` is an invariant of `glue f N₁ N₂`; crux lemma `sumOver_reindex` by list induction. Settle corollary `settle_ones_lifted` derived from the theorem and `settle_ones_decide` checked independently by `decide`. Not formalised: the pushout universal property (f is any covering place map), transition gluing, the marking-level consequence.

### Later
- Appendix E wording: "P-invariants of a component are still derivable from the composite's incidence matrix" — P2 shows this holds by *restriction* (composite → part), not by zero-extension (part → composite). Reword.
- Liveness does *not* lift — a formal counterexample to pair with P4.
- "The circuit dissolves the contextual boundary, not the ρ boundary" as a
  statement about the R1CS compiler, checked on pflow-rs.
- Lean for `pflow verify`'s `structural` verdicts: emit the invariant and
  its certificate, not just the verdict.
